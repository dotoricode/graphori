# 포지셔닝: 이 슬로건을 고른 이유

## 에이전트는 꼭 필요한 만큼만. 결과는 빠짐없이 검증합니다.

“계획·실행·검증”, “로컬 우선”, “재생 가능”, “적은 에이전트”는 유용한 제품 사실이지만 고유한 포지셔닝은 아닙니다. 현재 공개 도구인 [OSpec](https://github.com/clawplays/ospec), [Agentplane](https://github.com/basilisk-labs/agentplane), [agent-handoff](https://github.com/WillowRyu/agent-handoff), [Agent-Blackbox](https://github.com/TaewoooPark/Agent-Blackbox)도 각각 검증 흐름·로컬 근거·디스크 상태·재생 그래프를 전면에 둡니다.

Graphori의 더 좁은 주장은 배치 규율과 검증입니다. 에이전트 수 자체는 기능이 아니며, 독립적인 이득이 있을 때만 작업 그래프에 넣습니다. 업무일지는 각 결과가 실제 검증 상태에 도달했는지를 기록합니다.

보조 문구:

> Graphori는 코딩 작업을 그래프로 계획하고, 필요한 에이전트만 실행한 뒤 결과를 검증합니다.
