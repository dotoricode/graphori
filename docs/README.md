# Documentation

Read a plan as a plan and a verification record as a result. Where the two
disagree, the verification record wins.

## Start here

- [`public/`](public/README.md) — product guide, trust model, limitations, release gate
- [`architecture/`](architecture/README.md) — system structure and event contracts
- [`decisions/`](decisions/README.md) — the decisions that set current defaults

## Guides

- `GRAPHORI_FUNCTION_GUIDE.md` — what Graphori does today, separated from what is only designed
- `IMPLEMENTATION_PLAN.md` — implementation stages and their completion conditions
- `PROCESS.md` — the PR #2 working plan, its changes and checks

## Maintainer context

Written for people changing Graphori, not for people using it.

- `PRODUCT.md` — product boundaries and what is deliberately out of scope
- `DESIGN.md` — the design the current implementation follows
- `DESIGN_QA.md` — visual and interaction QA for the dashboard
- `TEAM_TOPOLOGY.md` — the role graph the coordinator plans against

## Browsing

`DOCS_VIEWER.html` renders these files with relative links intact.
`PROCESS_VIEW.html` opens `PROCESS.md` in it. `GRAPHORI_LEARNING_GAME.html` walks
through a recorded run.

## Archive

[`archive/`](archive/README.md) holds build reports, reviews, research
checkpoints, and preserved Doctori evidence. It is kept for provenance and is
not maintained.
