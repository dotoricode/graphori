Graphori는 한 사람이 모든 일을 순서대로 하는 대신, 작업 지시를 그래프로 나눕니다. 이 미션에서는 기획팀이 관제탑을 켜고, 필요한 팀이 앉아서 일하는 모습을 따라갑니다.

현재 사실실제 CLI는 worker 1개 · 아래 다섯 팀은 병렬 구조를 배우는 설계 시뮬레이션

지금 실제로 실행 가능

기본 CLI는 안전하게 worker 한 명을 실행합니다.

현재 저장소에서 바로 확인할 수 있는 최소 실행 경로입니다. 화면에 팀 다섯 명이 보여도, 기본 CLI가 자동으로 다섯 세션을 띄운다는 뜻은 아닙니다.

  • 터미널 명령 실행과 종료 결과 수집
  • JSONL journal에 사건과 digest 연결
  • status·replay --verify로 다시 계산
  • 대시보드 snapshot·SSE로 현재 상태 보기
실제 결과: learning-success · worker 1개 · terminal_status = succeeded
앞으로 만들고 싶은 구조

역할별 팀이 그래프의 각 노드에서 동시에 일합니다.

Graphori의 목표 경험입니다. 기획팀이 대시보드를 시작부터 관리하고, 독립 작업은 기다리지 않고 출발하며, 마지막에는 사람이 결과를 쉽게 이해합니다.

  • 기획팀이 graph version과 의존성 관리
  • 정보조사·설계·구현·검증 팀을 역할별로 분리
  • 독립 가지는 parallel_started로 함께 시작
  • fan-in 뒤에 다음 단계가 열리고 검증이 PASS
이 장면은 현재 기능이 아니라 설계 시뮬레이션입니다.

대시보드는 작업이 끝난 뒤 켜지는 화면이 아닙니다. 기획팀이 먼저 켜고, 사건이 들어올 때마다 현재 지도를 다시 그립니다.

다음 사건을 예측하려면 “작업 출발” 또는 “사건 한 칸”을 눌러 보세요.

작업이 끝난 뒤, 무엇을 물어볼까요?

정답을 맞히는 것보다 “왜 그렇게 생각했는지”가 중요합니다. 선택하면 실제 Graphori 코드와 연결된 설명이 열립니다.

질문 1 · 현실과 목표

화면에 다섯 팀이 보이면, 지금 기본 CLI가 다섯 세션을 실행한 걸까요?

선택하면 실행 코드와 연결해 설명합니다.

질문 2 · 세 가지 시계

학습용 pulse가 올라가면 진행률도 자동으로 올라가야 할까요?

liveness·progress·verdict를 구분해 보세요.

fan-in은 어떤 순간에 필요한 문일까요?

의존성이 모두 끝났는지 생각해 보세요.

코드 diff 대신, 끝난 일을 설명합니다.

미션이 완료되면 다음 세 문장으로 결과를 이해할 수 있습니다. “무슨 일을 했나?” “어떤 구조로 만들었나?” “왜 믿어도 되나?”를 먼저 보고, 원할 때만 raw evidence를 펼치세요.

무엇을 했나

worker가 hello를 출력

Graphori가 명령을 전달하고 stdout과 종료 상태를 모았습니다. 실제 자식 명령은 exit_code = 0으로 끝났습니다.

어떤 구조인가

10줄 사건 공책으로 연결

run_created부터 run_terminal까지 앞 사건의 digest와 다음 사건이 이어집니다. 이것이 현재 기본 CLI의 one-worker 구조입니다.

왜 믿나

다시 읽어도 같은 결과

replay --verify가 같은 projection digest를 확인했고 worker는 passed입니다. 독립 verifier의 최종 verdict는 아직 없습니다.

기술 증거를 펼쳐 보기
{
  "run_id": "learning-success",
  "command": "python3 -c 'print(\"Graphori worker created result\")'",
  "terminal_status": "succeeded",
  "exit_code": 0,
  "event_count": 10,
  "worker": "passed",
  "replay_verified": true,
  "independent_verdict": "pending",
  "journal": ".graphori/runs/learning-success/journal/journal.jsonl"
}

이 숫자는 화면 장식이 아니라 저장소에서 실제 실행한 성공 산출물의 핵심 값입니다. 현재 실행은 worker 한 명이며, 다섯 팀 장면은 설계 목표와 학습용 시뮬레이션으로 표시됩니다.
