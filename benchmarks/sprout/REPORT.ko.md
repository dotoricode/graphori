# Sprout 라우팅 모델 벤치마크

감사한 1,000칸 모델에서 무조건 파일럿은 대상 8개까지 v2보다 느렸고, 16개에서만
7.0% 빨랐습니다. 최종 adaptive 정책은 선언된 비용상 손익분기점을 넘기 전에는 v2를
그대로 사용해 이 예측 회귀를 피했습니다.

| 대상 수 | v1 target review | Graphori v2 | 무조건 파일럿 | Adaptive Sprout | Static oracle |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 234.0ms | **123.5ms** | 240.0ms | **123.5ms** | 125.0ms |
| 2 | 316.5ms | 206.0ms | 290.0ms | 206.0ms | **178.0ms** |
| 4 | 612.0ms | 395.0ms | 453.0ms | 377.5ms | **341.0ms** |
| 8 | 1,103.0ms | 776.0ms | 779.5ms | 703.5ms | **666.5ms** |
| 16 | 2,192.0ms | 1,539.0ms | 1,431.0ms | 1,389.0ms | **1,319.0ms** |

Adaptive Sprout의 v2 대비 모델링 지연 변화는 대상 1·2·4·8·16개에서 각각
0.0%, 0.0%, -4.4%, -9.3%, -9.7%였습니다. 40칸 중 파일럿을 사용한 수는 각각
0, 0, 3, 3, 3개입니다. 강화한 gate는 모델링 AI session이 v2보다 늘어나는 파일럿도
거부합니다.

16개 대상에서는 모든 조건이 선언 의무 3,520개를 덮었고 잘못된 fan-in 선언은
0개였습니다. Adaptive Sprout는 v2 대비 실행 노드를 3,520개에서 3,385개로 3.8%,
process 노드를 2,720개에서 2,630개로 3.3%, agent 노드를 800개에서 755개로 5.6%
줄였습니다.

이 결과는 실제 provider 시간, 토큰, 비용, 모델 품질을 증명하지 않습니다. 성능 gate와
벤치마크가 같은 추정치를 쓰므로 회귀 방지는 이 모델 안의 정책 불변식이지 독립적인
실측 속도 결과가 아닙니다.
